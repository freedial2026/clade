## Evidence

### Changed files

- `src/boat_prediction/entry_course.py` (new): `EntryCoursePrediction`
  (`lane_number` + `course_probabilities` over courses 1-6, validated to

  drifting apart).

### Decisions and risks

- **Sequencing exception, explicitly approved by the user**: the domain
  guide (line 1642) states P3 should start only once P2's forward test
  has proven stable. No real data exists in this environment to run
  that forward test at all, so this and all subsequent P3 tasks are
  built as synthetic-data-only scaffolding ahead of that documented
  prerequisite — flagged in the module docstring and here, not silently
  ignored. Before any real-money or production use, P2's forward test
  must actually be run and shown stable first.
- Uncertainty is measured via Shannon entropy over the 6-course
  distribution (max ~2.585 bits at uniform) with a default threshold of
  2.0 bits — a reasonable but arbitrary choice, fully overridable by the
  caller (not hardcoded into any decision path).
- Only per-boat marginal distributions are validated (each boat's own 6
  probabilities sum to 1). The joint constraint that only one boat can
  actually occupy each course in a single race (a permutation-matrix
  constraint) is not enforced here — that is a harder combinatorial
  problem out of scope for this task ("do not begin dependent tasks
  implicitly").
