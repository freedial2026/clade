# P1-T003: Feature availability tests

- Status: planned
- Model tier: sonnet (mechanical subtasks: haiku)
- Approval required: only if an important action is discovered
- Dependencies: see `tasks/BACKLOG.md`

## Goal

Prove that each feature was available at prediction time.

## Scope

Implement only this task. Do not begin dependent tasks implicitly.

## Acceptance criteria

- [x] Feature lineage exists
- [x] Leakage fixtures fail the gate
- [x] No post-result data is selected

## Evidence

### Changed files

- `src/boat_prediction/feature_availability.py` (new): `FeatureLineage`
  (feature_name, source, `TemporalRecord`, `is_result_derived`) is the
  lineage record. `check_feature_availability()`/`check_feature_set_availability()`
  raise `FeatureAvailabilityError` if a feature's `available_at` is
  after `prediction_at` (reusing `temporal.py`'s
  `is_available_for_prediction`), or if a result-derived feature is used
  before `race_finalized_at` (and requires `race_finalized_at <=
  prediction_at`). `FEATURE_SET_V1_NAMES` documents the §11.1 in-race
  base feature names, none of which are result-derived.
- `tests/test_feature_availability.py` (new, 8 tests) — two explicit
  leakage fixtures (a future-`available_at` feature, and an unfinalized
  result-derived feature) each proven to raise, plus a clean
  Feature-Set-V1-style fixture proven to pass.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 121 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- This is a reusable gate function, not yet wired into an actual
  feature-building pipeline (no such pipeline exists — no real data).
  Any future feature-extraction code must call
  `check_feature_set_availability()` before returning features to a
  model; that wiring is deferred.
- `race_finalized_at` is passed by the caller rather than inferred, since
  "when a race is finalized" is itself a data question (result
  confirmation) that belongs to the ingestion pipeline, not this gate.
