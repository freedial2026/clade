# P0-T008: Quarantine and replay

- Status: planned
- Model tier: sonnet (mechanical subtasks: haiku)
- Approval required: only if an important action is discovered
- Dependencies: see `tasks/BACKLOG.md`

## Goal

Quarantine invalid records and support corrected replay.

## Scope

Implement only this task. Do not begin dependent tasks implicitly.

## Acceptance criteria

- [x] Original failure is preserved
- [x] Replay is auditable
- [x] Successful replay does not duplicate valid data

## Evidence

### Changed files

- `src/boat_prediction/quarantine.py` (new): `QuarantineStore` persists
  quarantined records to a JSON ledger (`data/rejected/quarantine_ledger.json`
  by default). `add()` is keyed by hash(record, code) so re-adding the
  same failure doesn't duplicate. `replay()` accepts a corrected record
  and a caller-supplied `revalidate` predicate; on success it stores
  `corrected_record`/`replayed_at` alongside the untouched original
  `original_record`/`code`/`message`/`quarantined_at`, and replaying an
  already-resolved entry again returns the same result instead of
  creating a second accepted copy.
- `tests/test_quarantine.py` (new, 8 tests) — covers persistence,
  no-duplicate re-add, successful/failed replay, idempotent re-replay,
  unknown id, corrupt ledger, and reload-from-disk.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 71 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- This closes the persistence gap flagged in `tasks/P0-T007.md`
  (duplicate/referential checks only returned in-memory `.quarantined`
  lists; this task is where they'd be written to `data/rejected/`).
  Wiring `check_duplicates()`/`check_references()`/`validate_records()`
  output directly into `QuarantineStore.add()` calls was not done here —
  that's an integration step for whichever task first runs a real
  end-to-end batch (no real raw data exists yet to justify building that
  glue now); flagged rather than silently added.
- `revalidate` is caller-supplied rather than re-running a fixed
  validator, so `replay()` stays decoupled from `validation.py`/
  `integrity.py` and can be reused for any kind of quarantined record.
