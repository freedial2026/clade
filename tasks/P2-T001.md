# P2-T001: Odds snapshots

- Status: planned
- Model tier: sonnet (mechanical subtasks: haiku)
- Approval required: only if an important action is discovered
- Dependencies: see `tasks/BACKLOG.md`

## Goal

Store odds with source and exact availability timestamp.

## Scope

Implement only this task. Do not begin dependent tasks implicitly.

## Acceptance criteria

- [x] Prediction-time and closing odds are distinct
- [x] Missing snapshots are explicit
- [x] No future odds enter a historical decision

## Evidence

### Changed files

- `src/boat_prediction/odds.py` (new): `OddsSnapshot` (race_key,
  lane_number, odds, source, `TemporalRecord`, `is_closing`).
  `get_prediction_time_odds()` selects the latest snapshot available by
  `prediction_at` (reuses `temporal.py`'s `is_available_for_prediction`
  — a future snapshot can never win). `get_closing_odds()` selects the
  snapshot explicitly flagged `is_closing=True` (raises if more than one
  exists, since exactly one is expected). Both return an explicit
  `OddsQueryResult(found, snapshot, reason)` instead of `None`.
- `tests/test_odds.py` (new, 12 tests) — includes a dedicated test
  proving prediction-time and closing odds can differ for the same
  race/lane, and a test with a future-dated snapshot proving it's never
  selected for an earlier `prediction_at`.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 169 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- "Missing snapshots are explicit" is implemented as a result object
  with a `found` flag and `reason` string, not a bare `None` return —
  deliberately more verbose so callers can't silently treat a missing
  snapshot as falsy/zero.
- Multiple snapshots flagged `is_closing=True` for the same race/lane
  raise `OddsError` rather than picking one, since that would indicate a
  data problem (duplicate closing records) that should be caught, not
  silently resolved.
- No storage/persistence layer here (unlike `inventory.py`/`ingest.py`'s
  JSON ledgers) — this task is the query/selection logic only; snapshots
  are passed in as a plain list. Persisting real odds snapshots depends
  on a real odds data source, which doesn't exist in this environment.
