### Decisions and risks

- Reason codes reuse `docs/domain/.../implementation_guide.md` §9.3
  (`E001`-`E010`) only where a field's code is already defined there
  (`E003`, `E005`, `E006`). Other checks use locally-defined generic
  codes `E900` (type), `E901` (enum), `E902` (range) since the guide's
  table doesn't cover every generic case. **Risk:** if a future task
  assigns different meanings to `E900`-`E902`, this module's codes will
  need renumbering — flagged rather than guessed further.
  - Cross-record checks (duplicate lane numbers within one race,
  referential integrity against `racers`/`venues`) are explicitly out of
  scope — that's P0-T007.
- `RACE_ENTRY_SCHEMA` only covers `lane_number`/`registration_number`
  (the two fields with defined error codes); the full `race_entries`
  table (§7.2) has more columns that aren't validated yet since they
  don't have raw data or an assigned code yet.
