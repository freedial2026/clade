# P0-T004: Raw ingestion with idempotency

- Status: planned
- Model tier: sonnet (mechanical subtasks: haiku)
- Approval required: only if an important action is discovered
- Dependencies: see `tasks/BACKLOG.md`

## Goal

Store immutable raw records and import-run metadata.

## Scope

Implement only this task. Do not begin dependent tasks implicitly.

## Acceptance criteria

- [x] Reimport does not duplicate records
- [x] Raw payload and source lineage are retained
- [x] Partial failures are recoverable

## Evidence

### Changed files

- `src/boat_prediction/ingest.py` (new): `ingest_file()` copies one
  validated raw file into `data/staged/` and records a ledger entry keyed
  by `source_file_hash:parser_version` (source_file_hash, parser_version,
  relative_path, staged_path, ingestion_run_id, ingested_at). A repeat
  call for the same key returns the existing record unchanged.
  `ingest_directory()` runs this per-file, catching per-file
  `IngestionError`s into a `failed` list instead of aborting the batch.
- `tests/test_ingest.py` (new, 10 tests).
- `scripts/quality_gate.py`, `Makefile` (`lint` target): added `src` to
  the `compileall` check, which only covered `scripts`/`tests`/hooks
  before this task added application code.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 31 passed
- `python scripts/quality_gate.py` — passed
- Manual smoke test: batch with one valid `.txt` and one empty file —
  the valid file was staged and the empty one reported as a per-file
  failure (exit 1) without blocking the valid file; re-running the same
  batch produced identical output with no duplicate staging (idempotent).

### Decisions and risks

- "Raw payload... retained" is satisfied by copying (not moving/deleting)
  into `data/staged/`; the original `data/raw/` file is left untouched as
  the immutable source. No content parsing/normalization happens at this
  stage (out of scope; see pipeline stages after STAGED in the domain
  guide).
- Idempotency key is `(source_file_hash, parser_version)`, not just the
  file hash, per §9.2 of the domain guide — a parser version bump is
  treated as a legitimately new ingestion (re-ingest under upgraded
  parsing logic), while identical (hash, version) pairs are no-ops.
- "Partial failures are recoverable" is implemented at the file level
  (independent try/except per file in `ingest_directory`, non-zero exit
  only signals that *something* failed) rather than via a transactional
  batch/rollback mechanism, since there is no database yet to make
  batch atomicity meaningful.
- No DB, network, or archive-decompression (`.lzh`) handling was added;
  files are staged as opaque bytes.
