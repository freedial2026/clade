## Goal

Construct and calibrate exacta combination probabilities.

## Scope

Implement only this task. Do not begin dependent tasks implicitly.

## Acceptance criteria

- [x] Combination probabilities are coherent
- [x] Calibration is evaluated
- [x] Direct 120-class trifecta is not introduced

## Evidence

### Changed files

- `src/boat_prediction/exacta.py` (new): `construct_exacta_probabilities()`
  builds the 30-class joint distribution
  `P(first,second) = P(first) * P(second|first)` from a first-place
  distribution and a `ConditionalSecondPlaceModel` (P3-T002), then
  `_assert_coherent()` verifies it sums to 1.0 *and* that marginalizing
  over `second` for each `first` recovers the original first-place
  probability exactly (the chain-rule coherence check, not just a sum
  check). `evaluate_exacta_calibration()` reuses `calibration.py`'s
  `evaluate()` unchanged, since combinations are encoded as plain ints
  (`first*10+second`) rather than tuples.
- `tests/test_exacta.py` (new, 12 tests) — includes a dedicated
  `ScopeBoundaryTest` asserting exactly 30 combinations exist (not 120),
  and a test feeding a deliberately incoherent fake conditional model to
  prove the coherence check actually catches a broken input.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 274 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- Continues under the same **P3 sequencing exception** as P3-T001/T002
  (synthetic data only; see `tasks/P3-T001.md`).
- Chose an int encoding (`first*10+second`) over a `(first, second)`
  tuple specifically so `calibration.py`'s existing `int`-typed
  functions could be reused with zero changes to an already-completed
  task's file — a tuple label would have required widening
  `metrics.py`'s type hints.
- No trifecta (3連単) code exists anywhere in this module — the
  `ALL_COMBINATIONS` constant is asserted to have exactly 30 entries as
  a standing scope boundary, not just implied by the implementation.
