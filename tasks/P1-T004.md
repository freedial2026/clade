## Evidence

### Changed files

- `src/boat_prediction/model_comparison.py` (new): `run_comparison()`
  takes P1-T002's `Fold`s and one feature matrix/label vector, and fits
  a baseline model plus one or more named candidates on the *identical*
  train/test row indices per fold (Protocol-typed `fit`/`predict_proba`,
  no hard import dependency on lightgbm/catboost). `FoldComparisonResult.complexity_gain()`
  and `average_complexity_gain()` quantify baseline-minus-candidate
  log-loss. `lightgbm_model_factory()`/`catboost_model_factory()` are
  thin, lazily-importing adapters that raise a clear `ComparisonError`
  if the library isn't installed. No ensembling/blending code exists in
  this module at all.
- `pyproject.toml`: new `ml` extra (`scikit-learn`, `lightgbm`,
  `catboost` — scikit-learn is required by lightgbm's sklearn wrapper).
  Installed locally and verified (`lightgbm==4.7.0`, `catboost==1.2.10`,
  `scikit-learn==1.9.0`).
- `tests/test_model_comparison.py` (new, 11 tests): harness tests use
  small deterministic model doubles (`ConstantProbClassifier`,
  `FeatureLookupClassifier`) so they don't depend on any ML library
  being installed, plus end-to-end smoke tests that actually run
  `LGBMClassifier`/`CatBoostClassifier` through the harness (these two
  are not skipped in this environment, since both libraries installed
  successfully).

### Commands and tests

- `pip install -e ".[ml]"` — local, reversible, no production/paid

- `python -m unittest discover -s tests -p 'test_*.py'` — 132 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- **No real race data exists**, so the LightGBM/CatBoost end-to-end
  tests only prove the harness plumbing works (fit/predict_proba wiring,
  per-fold indexing) — the actual complexity-gain numbers from real
  data are unknown and will differ completely from anything in this
  environment's synthetic fixtures.
- The harness deliberately has **no** ensembling/blending function;
  "no fixed ensemble weights are assumed" is satisfied by omission, not
  by a configurable-but-defaulted weight. If future work wants an
  ensemble, that's new code elsewhere, not a hidden default here.
- Model interface is a `Protocol` (`fit`/`predict_proba`) rather than a
  concrete base class, so scikit-learn-compatible estimators (including
  ones not yet imagined) work without modification.
