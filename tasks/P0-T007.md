Detect duplicate races/entries and broken references.

## Scope

- [x] Exact and business-key duplicates are detected
- [x] Referential failures are quarantined

### Decisions and risks

- Quarantining here means "excluded from `.kept` and returned in
  `.quarantined` with a reason" — this task does not write to
  `data/rejected/` or a database (no ingestion pipeline wiring exists
  yet); that persistence step is implied by §9.3 of the domain guide but
  is not part of this task's scope and isn't separately backlogged, so
  it should be picked up when P0-T008 (quarantine and replay) or P0-T004
  ingestion is revisited with real data.
- Business-key duplicate detection takes the key function as a caller
  argument rather than being hardcoded to `RaceKey`, so it composes with
  `race_id.py` without a hard dependency between the two modules.
