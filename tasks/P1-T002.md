## Evidence

### Changed files

- `src/boat_prediction/walk_forward.py` (new): `generate_monthly_folds(dates, min_train_months=1)`
  produces one `Fold` per calendar month after a warm-up window,
  expanding-window style (`train_start` fixed at the earliest date,
  `train_end`/`test_start` growing each fold, `test_end` the next
  month's start). Purely a function of the input dates — no `random`
  module usage anywhere. `Fold.train_indices()`/`test_indices()` select
  by explicit date comparison.
- `tests/test_walk_forward.py` (new, 10 tests) — includes a same-input
  reproducibility test and a December→January month-rollover case.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 113 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- Chose expanding-window (train always starts at the earliest date) over
  a fixed-size rolling window, since the guide doesn't specify a window
  policy and expanding-window is the more common default for this data
  volume; a rolling window is a documented alternative if seasonality
  effects are found later.
- No actual model is trained/evaluated per fold here — that's P1-T001's
  baseline (or later models) combined with this fold generator, which
  isn't wired together yet since there's no real dataset to run it on.
