## Evidence

### Changed files

- `src/boat_prediction/paper_simulation.py` (new): `PaperSimulator`
  (constructor `stake_yen`/`daily_cap_yen`, defaults 100/1,200 per
  §16.1) — `stake_yen` is a single constant never mutated by any method,
  so there is no martingale/Kelly path even structurally.
  `record_outcome()` enforces max-one-bet-per-race and the daily cap
  (reset per calendar day of `decision_at`); a `void` result refunds the
  stake in full (net 0) rather than counting as a loss.
  `record_skip()` records skipped candidates (requiring a
  `skip_reason`). `BetRecord` carries every §16.2 field.
  `summarize()` computes `total_stake_yen`/`total_payout_yen`/
  `net_return_yen`, `max_drawdown_yen` (peak-to-trough over cumulative
  net PnL), and `max_win_streak`/`max_loss_streak` (consecutive win/loss
  only, excluding void and skipped records).
- `tests/test_paper_simulation.py` (new, 16 tests) — includes a
  hand-computed example (5 bets: 2 wins, 2 losses, 1 void, plus 1 skip)
  verified against manually calculated totals, drawdown, and streaks.

### Commands and tests

- `python -m unittest discover -s tests -p 'test_*.py'` — 223 passed
- `python scripts/quality_gate.py` — passed

### Decisions and risks

- "Max 1 bet per race" is enforced against `race_id` permanently (a set
  that is never reset), not per-day, since `race_id` already encodes the
  race date (P0-T003's canonical key) and can only ever occur once
  historically.
- Win/loss streaks exclude `void` records entirely (a refund is neither
  a win nor a loss) — this is a modeling choice since the guide doesn't
  define streak semantics explicitly; flagged for review once real
  results exist.
- No HTTP client, broker SDK, or external API call exists in this
  module or anywhere in the codebase — "no betting integration" is
  satisfied by omission, matching `docs/PROJECT_PROFILE.md`'s "does not
  automate betting in the initial scope."
- Purely in-memory; no persistence layer was added here (unlike e.g.
  `ingest.py`'s JSON ledger) since there's no real prediction pipeline
  yet to generate real `BetCandidate`s from.
