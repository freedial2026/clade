# モデル・トークン運用方針

## 既定ルーティング

| タスク | モデル | 理由 |
|---|---|---|
| ファイル探索、整形、分類、ログ要約 | Haiku | 高速・低コストで十分 |
| 通常実装、バグ修正、テスト、レビュー | Sonnet | 品質と費用の標準点 |
| 複雑な設計、不可逆判断、高リスク分析 | Opus | 必要時だけ高い推論能力 |

## Opusへ上げる条件

次のいずれかを満たし、Sonnetでの分割・追加調査では不足すると判断した場合だけ使用します。

- 複数システムをまたぐ不可逆なアーキテクチャ変更
- セキュリティ、認証、重大なデータ損失リスク
- 原因候補が多く、通常デバッグで収束しない重大障害
- 高額な運用コストや長期ロックインを伴う選択

## 入力量削減

- 全リポジトリではなく、`repo_map.py`と`rg`で候補を絞る。
- ログは`summary_logs.py`でエラー周辺と頻度へ圧縮する。
- 差分中心でレビューし、未変更ファイルを再読込しない。
- タスク・ADR・handoffに決定を残して再推論を防ぐ。
- 大量変換はPythonで実行し、モデルには仕様・例外・集計だけ渡す。
